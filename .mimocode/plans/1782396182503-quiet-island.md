# Plan: Fix ESP32 Stale Session + Firebase Verification

## Problem Analysis

### Bug 1: "ESP32 in use" when powered off + auto-activates Run

**Root cause** — Two compounding issues:

1. **Stale sessions in registry**: `session_registry.json` contains sessions with `"status": "running"` that were never ended (e.g., ESP32 powered off mid-session). When the backend restarts or frontend loads, these stale sessions persist.

2. **`loadBackendCatalog` auto-sets `activeRun`** (`App.jsx:383-395`): On page load, it queries `/sessions`, finds sessions with `status === "running"`, and automatically sets `activeRun.sessionId`. This makes the dashboard show "ESP32 in use" and disable the Run button — even when ESP32 is off.

3. **`visibleSessionId` uses `activeSessionId` unconditionally** (`Dashboard.jsx:224`): `activeSessionId` (from `activeRun`) takes priority over ESP32-reported sessions. So even if ESP32 status says no active session, the stale `activeRun` keeps the dashboard in "in use" state.

### Bug 2: Firebase data writing

The Firebase write path is: `process_telemetry()` → `firebase.write_latest_telemetry()` + `firebase.append_live_telemetry()`. On session end: `firebase.finalize_session_telemetry()` moves RTDB packets to Firestore.

The code is correct. But the stale "running" session from Bug 1 means `end_session()` was never called, so `finalize_session_telemetry()` never ran for that session. Telemetry packets may be orphaned in RTDB.

## Changes

### 1. `backend/services/sessions.py` — Clean up stale sessions on startup

Add a function to detect and mark stale sessions. When `list_all_sessions()` is called, or when the backend starts, check if any "running" sessions belong to devices that are no longer fresh. If so, mark them as "interrupted".

```python
def cleanup_stale_sessions() -> int:
    """Mark running sessions as interrupted if their device is stale."""
    from services.mqtt_service import mqtt_service
    count = 0
    for session_id, session in list(local_sessions.items()):
        if session.get("status") != "running":
            continue
        device_id = session.get("device_id") or mqtt_service.session_devices.get(session_id)
        if device_id and mqtt_service.active_session_for_device(device_id):
            continue
        # Device is stale or unknown — mark session as interrupted
        session["status"] = "interrupted"
        session["ended_at"] = datetime.now(UTC).isoformat()
        remember_session_owner(session_id, session.get("user_id", ""), session)
        firebase.update_session(session_id, {
            "status": "interrupted",
            "ended_at": session["ended_at"],
        }, session.get("user_id", ""))
        mqtt_service.clear_active_session(session_id)
        count += 1
    return count
```

Call this on `start_session()` and `list_all_sessions()` to keep registry clean.
